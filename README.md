## ⚡ Key Features

| Feature | Description |
| :--- | :--- |
| 🛡️ **Risk Exposure & Severity Scoring** | Automatically flags critical liabilities (unlimited indemnity, uncapped liability, unilateral termination, IP transfers, non-competes) with High/Medium/Low severity ratings, confidence levels, and actionable negotiation advice. |
| 📑 **Executive Synthesis** | Distills complex agreements into plain-English commercial summaries: parties, effective dates, governing law, payment terms, duration, and renewal conditions. |
| 📋 **Bilateral Obligation Matrix** | Parses who owes what (Vendor vs Client), categorizing commitments by priority levels, deadlines, and conditional triggers. |
| ⏰ **Deadline & Milestone Extraction** | Extracts critical milestones including effective dates, renewal notice windows, Net-30 payment deadlines, and audit periods. |
| 🏷️ **Clause Taxonomy & Classification** | Categorizes legal clauses using zero-shot NLI models (`valhalla/distilbart-mnli-12-3` / `facebook/bart-large-mnli`) or domain-fine-tuned checkpoints across standard commercial categories. |
| 💬 **Grounded RAG Q&A ("Ask AI")** | Multi-turn legal chat assistant strictly grounded in document vectors with verifiable page numbers and clause section citations to prevent hallucinations. |
| ⚖️ **Contract Comparison & Redlining** | Side-by-side contract diffing highlighting inserted, modified, or deleted clauses between document versions. |
| 📄 **One-Click Executive Report Export** | Generates cleanly structured Markdown audit reports for sharing with legal counsel, stakeholders, or procurement teams. |
| 📊 **Legal Command Center** | Real-time analytics dashboard displaying contract portfolio metrics, risk distributions, and pending obligations. |

### Request Flow: Ingestion to Grounded RAG
1. **Upload**: User uploads `.pdf` or `.docx` contract via the frontend upload zone.
2. **Extraction & Normalization**: Backend extracts raw text, detects structural sections, and estimates page boundaries.
3. **Semantic Chunking**: Contract text is partitioned into overlapping semantic chunks (default ~800 chars, 100 overlap).
4. **Vector Embedding**: Chunks are embedded with `sentence-transformers/all-MiniLM-L6-v2` and indexed in **ChromaDB** tagged by `contract_id`.
5. **Intelligent Querying**: User queries are embedded, relevant top-$k$ chunks are retrieved via vector similarity, and fed into the unified LLM prompt.
6. **Structured Output**: Grounded response returned with exact page numbers, section citations, and risk tags.

## 🛠️ Tech Stack

### Frontend
- **Framework**: [React 18](https://react.dev/) + [TypeScript](https://www.typescriptlang.org/)
- **Bundler & Dev Server**: [Vite 6](https://vitejs.dev/)
- **Styling**: [Tailwind CSS 3](https://tailwindcss.com/)
- **Routing**: [React Router v7](https://reactrouter.com/)
- **Icons**: [Lucide React](https://lucide.dev/)
- **Hosting**: [Vercel](https://vercel.com/)

### Backend
- **Framework**: [FastAPI](https://fastapi.tiangolo.com/) (Python 3.12)
- **ASGI Server**: [Uvicorn](https://www.uvicorn.org/)
- **Validation & Settings**: [Pydantic v2](https://docs.pydantic.dev/) + `pydantic-settings`
- **Document Parsing**: [PyMuPDF (fitz)](https://pymupdf.readthedocs.io/) & [python-docx](https://python-docx.readthedocs.io/)
- **Testing**: [pytest](https://docs.pytest.org/) & `httpx`

### AI, Vector Store & NLP
- **Vector Database**: [ChromaDB](https://www.trychroma.com/) (with lightweight in-memory fallback)
- **Embedding Models**: `sentence-transformers/all-MiniLM-L6-v2`
- **Zero-Shot Classification**: `valhalla/distilbart-mnli-12-3` (default lightweight) / `facebook/bart-large-mnli` (optional local `LegalBERT`/`RoBERTa` fine-tuned checkpoints)
- **LLM Providers**: Groq (`qwen/qwen3.8-27b`, `openai/gpt-oss-120b`), Google Gemini (`gemini-2.0-flash`), Anthropic Claude (`claude-sonnet-5`), OpenAI (`gpt-4o-mini`), or offline Mock fallback

## 🚀 Getting Started

### Prerequisites
- **Python**: Version `3.12+` recommended
- **Node.js**: Version `18.x` or `20.x`
- **Package Managers**: `pip` and `npm`

---

### 1. Backend Setup

Open a terminal in the root directory:

```bash
# Navigate to backend directory
cd backend

# Create and activate a virtual environment
# Windows (PowerShell):
py -3.12 -m venv venv
.\venv\Scripts\Activate.ps1

# Linux / macOS:
python3 -m venv venv
source venv/bin/activate

# Install core dependencies
pip install -r requirements.txt
```

> **Optional ML Stack**: If you wish to use local Sentence-Transformers and ChromaDB on your machine instead of the built-in lightweight vector fallback:
> ```bash
> pip install -r requirements-ml.txt
> ```

#### Configure Environment Variables
Copy `.env.example` to `.env`:

```bash
cp .env.example .env
```

Configure your preferred LLM provider in `.env`:
```env
# Supported: groq, gemini, anthropic, openai, mock
LLM_PROVIDER=groq
GROQ_API_KEY=gsk_your_groq_api_key_here
LLM_MODEL=qwen/qwen3.8-27b

# Enable deterministic offline fallback when API keys are absent:
MOCK_FALLBACK=false
```

#### Run the Backend Server
```bash
uvicorn app.main:app --reload --port 8000
```
API server will be live at `http://localhost:8000`.
Interactive Swagger documentation is available at `http://localhost:8000/docs`.

---

### 2. Frontend Setup

In a new terminal window:

```bash
# Navigate to frontend directory
cd frontend

# Install dependencies
npm install

# Start Vite development server
npm run dev
```

The frontend application will launch at `http://localhost:5173`.

> **API Target**: By default, the frontend sends requests to `http://localhost:8000`. To point to a custom or deployed backend, set `VITE_API_URL` in `frontend/.env`:
> ```env
> VITE_API_URL=https://your-backend-api.up.railway.app
> ```

## 🧠 Model Transparency & Methodology

- **Honesty in AI**: No model in this repository is claimed to be "trained from scratch".
- **Embeddings**: Employs pretrained `sentence-transformers/all-MiniLM-L6-v2` for dense vector indexing.
- **Zero-Shot Classification**: Uses `facebook/bart-large-mnli` to classify arbitrary contract clauses without fine-tuning overhead.
- **Generative Synthesis & RAG**: Context is retrieved via strict vector matching and provided in system prompts to LLMs (Groq / Gemini / Claude / OpenAI) with strict instructions to cite sources and reject unsupported claims.
- **Local Fine-Tuning Pipeline**: The `backend/train/` directory provides reproducible data preparation and PyTorch fine-tuning scripts for teams wanting to train custom `LegalBERT` models on specialized legal taxonomies.
